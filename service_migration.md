# Homelab service migration to NixOS

Assessment of the Compose projects under `/mass/config/homelab` on `h0t2`, ordered roughly from easiest to hardest to run natively. “Native” means a NixOS-managed package/systemd service, not a container. The NixOS option/package checks refer to this repo's locked nixpkgs revision.

## Summary

- **Already declared native in this repo:** Newt, LanguageTool, Paperless, PostgreSQL, Radicale, Shogging, Perfect Smithing, and Signal Whisper are included by `modules/hosts/h0t2/configuration.nix`. Their live deployment status was not verified.
- **Docker `frontend` networks are Compose plumbing.** They can go away for native services; connect services to localhost and configure the native ingress instead. **Gluetun is different:** qBittorrent and Prowlarr currently share its VPN network namespace, so preserve the VPN egress/kill-switch boundary if migrating them.
- **Do not copy PostgreSQL data directories between images/versions.** Use a stopped, verified logical dump/restore when changing PostgreSQL major version, image, or extensions. The repo already has a shared NixOS PostgreSQL instance at `/mass/data/postgres-shared`.
- I could inspect Compose files and directory names, but `docker ps` failed because the SSH account cannot access the Docker socket. This is a config-based ranking, not a confirmation of which containers are running.

## Migration notes

1. Before each cutover, stop the old app cleanly, take a backup, record the image/app version, and check data-directory ownership. Never let Docker and the native unit write the same state at once.
2. For PostgreSQL, distinguish filesystem reuse from logical migration. The Immich, PinePods, and Shareloop images use different PostgreSQL versions/extensions; the repo's shared cluster is not a drop-in replacement for their raw data directories.
3. Drop Compose-only `frontend` networks when replacing the Docker ingress; bind native backends to loopback where practical and update proxy targets. For Servarr, separately preserve Gluetun's VPN-only routing and kill switch—removing Docker networking must not accidentally send torrent traffic over the normal host route.
4. Keep credentials out of Nix store literals. Use the repo's agenix pattern or systemd `LoadCredential`/environment files with restricted permissions.

### Immich PostgreSQL compatibility

The live Immich database reports PostgreSQL `14.19`, `vchord=0.4.3`, and `vector=0.8.1`. Nix would use PostgreSQL `17.11`, VectorChord `1.1.1`, and pgvector `0.8.6`. **The versions/extensions are compatible with current Immich:** upstream documents PostgreSQL `>=14,<20`, VectorChord `>=0.3,<2.0`, and pgvector `>=0.7,<0.9`; all Nix versions fit those ranges. The NixOS Immich module installs both extensions, preloads VectorChord, runs `ALTER EXTENSION ... UPDATE`, and reindexes the face/clip indexes when VectorChord changes.

That does **not** make the PostgreSQL data directory portable: PostgreSQL 14 files cannot be opened by PostgreSQL 17.11. Migrate Immich with a logical dump/restore into the NixOS-managed database (or a carefully planned `pg_upgrade`), after a verified backup. The VectorChord 1.1.1 update scripts include the `0.4.3 → 0.5.0 → 0.5.1 → 0.5.2 → 0.5.3 → 1.0.0 → 1.1.0 → 1.1.1` path; test the restore and the NixOS module's extension/reindex steps on a copy before cutover.

Sources: [Immich PostgreSQL requirements and extension compatibility](https://docs.immich.app/administration/postgres-standalone/), [Immich upgrade guidance](https://docs.immich.app/install/upgrading/), and [Jellyfin 12.0 upgrade notes](https://jellyfin.org/posts/jellyfin-release-12.0/).
